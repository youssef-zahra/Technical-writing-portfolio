# Technical Writing Portfolio

A set of writing samples built to show range across the formats technical teams actually need: explainers, engineering narratives, and tutorials.

## Background

10+ years writing technical documentation and developer-facing content, including docs-as-code environments, embedded engineering sprint cycles, and hands-on work with Docker, Kubernetes, Helm, and observability tooling.

The samples here come from a simple idea. Good technical writing means being curious enough to understand a concept properly, and skilled enough to explain it simply, without needing to be the engineer who built it.

## What's here

- /explainers: "What is X?" style pieces that break down a technical or conceptual topic clearly and concisely
- /engineering-narratives: "Why we did X" pieces that tell the real story behind a technical decision, including the problem, the investigation, the fix, and the result
- /tutorials: step-by-step, use-case-driven guides aimed at a builder actually doing the task, not just reading about it

## Approach

Each piece is built to be genuinely useful to a technical reader first. That means clear, extractable answers up front, real specifics over generic summaries, and formatting that respects the reader's time.
